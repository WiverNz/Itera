# CI recommendations

CI is not required to implement any issue, but it is what keeps the guarantees in `00-strategy.md` real. Set up in issue 001 (basic) and completed in issue 039.

## 1. Pipeline

GitHub Actions, one workflow, on every push and pull request.

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '17' }
      - uses: gradle/actions/setup-gradle@v4
      - run: ./gradlew --no-daemon lintDebug
      - run: ./gradlew --no-daemon testDebugUnitTest
      - run: ./gradlew --no-daemon verifyRoborazziDebug
      - run: ./gradlew --no-daemon koverVerify
      - run: ./gradlew --no-daemon assembleDebug
      - uses: actions/upload-artifact@v4
        with: { name: reports, path: app/build/reports/** }
```

Instrumented tests run on a separate, slower job using `reactivecircus/android-emulator-runner` on API 34, triggered on pull requests to `main` and nightly - not on every push, because an emulator boot dominates the run.

## 2. Gates

| Gate | Fails the build |
| --- | --- |
| Compilation | yes |
| `lintDebug` | yes - `HardcodedText` and `MissingTranslation` are errors |
| Unit tests | yes |
| `domain` coverage < 85 % | yes |
| Instrumented tests (PR to main) | yes |
| Room schema JSON changed without a migration | yes - a check that `app/schemas` diff implies a new `Migration` |
| A golden image differs | yes - re-recording must be deliberate and explained (`04-visual-regression.md`) |
| A string exists in `values/` but not in all three other locales | yes - `MissingTranslation` lint plus `TranslationCompletenessTest` |
| APK size regression > 10 % | warn |

## 3. Static checks

- **Android Lint** with a project `lint.xml` raising `HardcodedText`, `MissingTranslation`, `ContentDescription`, `TouchTargetSizeCheck` and `UnusedResources` to error.
- **ktlint** or **spotless** for formatting, with `--format` available locally and a check in CI. Configure once in issue 001 so no later issue debates style.
- **`ArchitectureTest`** runs as an ordinary unit test, so no extra tooling is needed for boundary enforcement.

Detekt is optional. If added, start from a minimal ruleset - a large default ruleset generates noise that gets suppressed, which is worse than no check.

## 4. Coverage

Kover (Kotlin-native, works with the Compose compiler without exclusion gymnastics):

```kotlin
kover {
    reports {
        verify {
            rule("domain line coverage") {
                bound { minValue = 85; coverageUnits = LINE }
                filters.includes.classes("com.wivernz.itera.domain.*")
            }
        }
    }
}
```

Only `domain` is gated, deliberately (`00-strategy.md` section 8).

## 5. Build reproducibility

- The Gradle wrapper is committed and its checksum verified in CI.
- `dependencyResolutionManagement` already uses `FAIL_ON_PROJECT_REPOS`.
- Version catalog pins every dependency; no dynamic versions, no `+`, no snapshots.
- Consider `--write-verification-metadata` once the dependency set settles.

## 6. Release builds

Not automated in the MVP. Issue 040 documents the manual steps: version bump, signing config from a local keystore (never committed, never in CI secrets until there is a real release channel), `assembleRelease`, `bundleRelease`, and the manual QA checklist.

When a release channel exists, the signing key goes in GitHub encrypted secrets and a tag-triggered job builds the AAB. Not before - an unused signing key in CI is a liability.

## 7. What CI must not do

- Post anything to an external service beyond the repository host.
- Run the app against any network endpoint (there is none).
- Auto-merge, auto-format on `main`, or auto-bump dependencies without review.
